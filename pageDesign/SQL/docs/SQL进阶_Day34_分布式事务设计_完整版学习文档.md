# 三、为什么产生分布式事务


单体应用：

```
一个数据库

一个事务
```


容易保证一致。


微服务：


```
订单服务

数据库A


库存服务

数据库B


支付服务

数据库C
```


一个业务：

多个数据库。

# 五、CAP理论


CAP：


## Consistency


一致性。


所有节点看到相同数据。


---

## Availability


可用性。


服务持续响应。


---

## Partition tolerance


分区容错。


网络异常情况下继续工作。


---

# 六、BASE理论


BASE：

最终一致性思想。


包含：

## Basically Available

基本可用。


## Soft State

软状态。


## Eventually Consistent

最终一致。


---

# 七、2PC两阶段提交


Two Phase Commit。


两个阶段：


## 第一阶段：准备


参与者：

准备提交。


## 第二阶段：提交


协调者：

通知提交。


---

# 八、2PC问题


缺点：


## 1.性能差


等待时间长。


## 2.单点问题


协调者故障。


## 3.锁时间长


---

# 九、3PC


改进2PC。


增加：

预提交阶段。


减少阻塞。


但是：

实现复杂。


---

# 十、TCC模式


TCC：

Try

Confirm

Cancel


---

# Try


预留资源。


例如：

冻结库存。


---

# Confirm


确认执行。


例如：

扣减库存。


---

# Cancel


取消。


例如：

释放库存。


---

# 十一、Saga模式


长事务拆分。


每一步：

有补偿操作。


例如：


```
创建订单

↓

扣库存


失败：

补偿恢复库存
```
