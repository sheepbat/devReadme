# 三、为什么需要消息队列


同步调用问题：


订单创建：


```
创建订单

↓

扣库存

↓

发送通知

↓

生成积分
```


所有步骤同步：

响应慢。


---

# 四、引入消息队列


架构：


```
订单服务

↓

MQ

↓

库存服务

通知服务

积分服务
```


优势：

- 异步
- 解耦
- 削峰


---

# 五、消息队列核心概念


## Producer


生产消息。


例如：

订单服务。


---

## Consumer


消费消息。


例如：

库存服务。


---

## Topic


消息分类。


例如：

```
order-created
```

# 七、数据库与MQ一致性问题


问题：

数据库成功。

消息发送失败。


或者：

消息成功。

数据库失败。


产生：

数据不一致。


---

# 八、解决方案


# 方案1：本地消息表


流程：


```
业务数据

+

消息记录

同一个事务保存
```


然后：

异步发送消息。

# 十三、MQ消费问题

原因：

# 十四、消息幂等


例如：

订单状态更新。


SQL：


```sql
UPDATE orders

SET status=2

WHERE id=1

AND status=1;
```


重复执行：

结果安全。
