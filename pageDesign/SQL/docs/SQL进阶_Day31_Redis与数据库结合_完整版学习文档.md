# 七、知识点详细讲解


# 1.Redis适合存什么


适合：

- 热点数据
- 查询结果
- Session
- 验证码
- 计数器


不适合：

核心交易数据。


---

# 2.Cache Aside模式


企业最常用。


读取：


```
查缓存

↓

没有

↓

查数据库

↓

更新缓存
```


更新：


```
更新数据库

↓

删除缓存
```


---

# 3.为什么删除缓存


如果：

先更新缓存。

再更新数据库。


可能：

数据不一致。


推荐：

数据库成功后删除缓存。


---

# 八、缓存一致性问题


## 问题1：更新数据库失败


流程：

删除缓存。

更新数据库失败。


结果：

缓存不存在。


下一次重新加载。


---

## 问题2：并发更新


两个线程：

同时修改。


可能：

旧数据覆盖新数据。

# 十、缓存击穿


定义：

热点Key失效。


例如：

热门商品。


大量请求同时访问数据库。


解决：

- 互斥锁
- 热点永不过期


---

# 十一、缓存雪崩


定义：

大量Key同时失效。


原因：

统一过期时间。


解决：

随机过期时间。
