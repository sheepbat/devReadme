# 四、主从架构


典型结构：


```
客户端

  |

应用服务

  |

 +----------+

 |          |

主库       从库

写          读

```


---

# 五、复制原理


流程：


```
Master

执行SQL

↓

写Binlog

↓

Slave IO线程读取

↓

Relay Log

↓

Slave SQL线程执行

```


---

# 六、核心组件


## 1.Binlog


主库产生。


记录：

- 数据变化
- DDL
- DML


---

## 2.IO线程


负责：

读取主库binlog。


---

## 3.Relay Log


从库中转日志。


---

## 4.SQL线程


执行日志。


完成数据同步。


---

# 七、复制模式


# 1.异步复制


默认方式。


流程：

主库提交。

立即返回。


从库慢慢同步。


优点：

性能高。


缺点：

可能丢数据。


---

# 2.半同步复制


主库等待至少一个从库确认。


提高安全。


---

# 3.同步复制


等待所有节点。


性能低。


---

# 八、GTID复制


GTID：

Global Transaction Identifier。


作用：

唯一标识事务。


格式：


```
server_id:transaction_id
```


优势：

- 自动定位
- 故障恢复简单

# 十、主从延迟


问题：

主库写入。

从库还没同步。


表现：

刚写入。

查询不到。


---

# 十一、延迟原因


## 1.从库性能不足


例如：

CPU低。


---

## 2.大事务


例如：

一次更新百万数据。


---

## 3.网络问题


同步慢。


---

# 十二、延迟优化


方案：


## 1.优化SQL


减少大事务。


## 2.提升从库性能


增加资源。


## 3.拆分业务


降低压力。
